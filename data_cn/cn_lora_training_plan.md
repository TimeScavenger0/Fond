# 中文 LoRA 多域续训方案（定稿待评审）

## 一、总体策略与边界

本阶段不重训 FontDiffuser 扩散，只在现有拉丁 LoRA 上做中文多域续训。基础 CLIP（ViT-B/32）全程冻结，可训练参数沿用现有冻结口径：LoRA 适配矩阵（`lora_proj`，r=256、alpha=1024，作用于 q/k/v/out）、视觉投影 `visual.proj`、文本端 `ln_final`。起点权重为 `model_checkpoints/fontclip_lora_best.pt`，通过 `Config.checkpoint_path` 加载，模型结构与权重一致，可直接 `load_state_dict` 续训。

这样设计的依据是：拉丁能力已编码在已加载的 LoRA 权重里，基础 CLIP 不动；中文续训只在低秩增量上叠加，配合拉丁 replay 与小学习率，可把对拉丁功能的扰动降到最低，满足"原始功能不受影响"。

## 二、多域数据混合（防拉丁退化）

中文训练集 14 个字体，拉丁训练集 88 个字体。若直接混合全部拉丁样本，中文会被数量淹没；若只用中文，则拉丁能力存在被覆盖风险。方案是构建一个受控的混合数据集，中文 14 字体全部保留，拉丁按固定随机种子抽取一个子集（建议 20–28 个字体），并通过采样权重让每个训练步内中文与拉丁样本近似平衡（目标中文占比不低于 40%）。

工程上已确认中文与拉丁字体主名零冲突，两套图可放进同一图像目录。落地步骤为写一个数据准备脚本，生成混合属性 JSON（中文 train JSON 与拉丁子集 JSON 合并），并在同盘用硬链接（`os.link`，不占额外空间、不需管理员权限）把 `cn_images` 与 `gwfonts_images` 的对应 PNG 汇集到 `mixed_images`；`font_dir` 直接传中文绝对路径与拉丁 gwfonts 路径组成的列表（MyDataset 已支持 list），无需复制字体文件。混合比例、拉丁子集名单、随机种子全部写入 meta，保证可复现。

## 三、数据增强适配

现有拉丁增强含 `RandomRotation(180)`，对中文方块字过于激进：汉字倒置后结构与语义完全破坏，会引入大量"倒置汉字"噪声。方案把旋转限制在小角度区间（建议 ±10°，用于覆盖真实倾斜而非任意视角），或在主配置中关闭大角度旋转；保留 `RandomResizedCrop`（正方形、ratio=1.0，scale 下限沿用现有口径），使其能在单字网格与整段短文上裁到单字或局部。ColorJitter 默认关闭，与拉丁主配置一致。是否保留小角度旋转作为一个消融项，用验证相关性决定。

## 四、针对属性纠缠与复杂结构的可消融模块

这是本阶段的创新点，采用分模块、可独立开关、可消融的设计，避免一次性堆叠导致无法归因。

### 模块 A：属性方向正交化（针对属性纠缠）

属性纠缠的机理是联合嵌入空间里共现属性的方向不正交，沿一个属性移动会在其他属性方向产生投影。模块在归一化嵌入空间估计每个属性的方向向量（优先用文本端 `encode_text("a font") − encode_text("not a font")`，稳定且不依赖额外标注），对属性方向矩阵 D 施加软正交约束 `loss_orth = ||DᵀD − I||_F²`。考虑到部分属性客观相关，采用软权重而非强制完全正交，并优先对经验上易纠缠的属性对（如 serif/formal、thin/delicate、strong/angular）施加。该模块计算轻、可解释，直接对应"降低属性间耦合"这一目标。

### 模块 B：独立属性判别头（针对纠缠，兼可解释）

在归一化图像特征上为每个参与训练的属性接一个轻量线性二分类头，用真实属性值（按阈值二值化）做独立 BCE 监督，迫使共享特征中每个属性都能被独立读出，减少信息在单一向量上的混叠。判别头参数少，适配 24 字体的小数据集，同时输出可直接作为属性预测结果，增强可解释性。验证口径为每属性的预测相关性与区分度。

### 模块 C：内容—风格子空间分离（针对复杂结构保护）

利用数据的天然结构：同一字符跨字体（内容恒定、风格变化）与同一字体跨字符（风格恒定、内容变化）。通过两组对比约束，让内容分量在同字符跨字体时稳定、风格分量在同字体跨字符时稳定，并约束两个子空间正交。这与 FontDiffuser 的 SCR 解耦思想呼应，但落在 LoRA 特征层而非扩散网络。目标是让推理优化时风格更新主要作用于风格分量，内容结构（尤其鑫、森、品、众等复杂交叉结构）不被非刚性变形破坏。

### 模块 D：结构锚定正则

对复杂字符，在内容子空间约束其内容分量相对种子锚点稳定，风格更新不得带动内容分量漂移，作为模块 C 的强化项，专门针对论文指出的复杂交叉、圆转笔画失败问题。模块 C、D 可合并开关，先验证 C 再决定是否加 D。

## 五、训练阶段与超参

分阶段推进，每阶段独立保存权重并记录，便于回退与消融。

| 阶段 | 内容 | 目的 |
| --- | --- | --- |
| S0 | 混合数据 + 小学习率续训，仅主 BCE 对比损失 | 验证中文图文对齐、拉丁不退化，跑通管线 |
| S1 | 加模块 A（属性方向正交） | 验证属性纠缠是否缓解 |
| S2 | 加模块 B（独立判别头） | 验证属性独立可判别性 |
| S3 | 加模块 C/D（内容-风格分离、结构锚定） | 验证复杂结构保护 |

学习率取比拉丁首训更小的值（建议 1e-5 量级，作为超参在小步实验中确定），保护已有 LoRA；沿用两阶段学习率，60% 后按 end_factor 衰减；batch size 结合混合后字体数与 CPU/单卡显存确定，小数据集注意避免过拟合。每个阶段都做完整消融（开/关对应模块），并在固定的 validation/test 字体上评估。

## 六、验证指标与基线对照

主指标沿用现有属性相关性（`evaluate_correlation_coefficient`），分别在中文与拉丁验证集上计算。针对纠缠新增属性间条件相关度量：固定或匹配其他属性后，考察目标属性的独立响应，对比训练前后属性方向的正交程度。针对复杂结构，用字形可辨认度与复杂字符结构保持指标（拓扑/笔画连通性、与参考内容的结构偏差）。拉丁回归测试用于确认训练后拉丁任务不退化。

所有结果与零样本基线（当前拉丁 LoRA 不做中文训练直接用于中文，即此前实测的 40 步/300 步结果）对照，数据一律来自实际实验，不做估算填充。留空的 7 个属性（bad、capitals、cursive、display、fresh、friendly、gentle）本阶段不参与训练，是否低置信度补全另行决策。

## 七、待确认事项

拉丁 replay 子集的具体规模、模块 A 软正交的权重、是否保留小角度旋转，建议在本地先用极小步数跑通后，用验证结果确定，而非现在拍死。云 GPU 预算与时间范围在本地方案与代码全部跑通后再确认。
